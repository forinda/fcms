# AGENTS.local.md — rules this project learned the hard way

`.agents/AGENTS.md` is regenerated by `kick g agents -f`, so anything written
there is lost on the next run. This file is not, and it holds the conventions
that came out of bugs rather than out of a template.

## Time belongs to the database

**Anything compared against a column the database stamped must be compared using
the database's clock.**

`workflow_runs.runAt` is `defaultNow()`, and the queue claimed rows with
`lte(runAt, new Date())` — a `Date` from the Node process. Two clocks then
decide whether a run is due, and a database a few milliseconds ahead makes a
run that was just enqueued invisible until the difference passes. Every local
run was green, because locally both clocks are the same one. CI, where the
database is a service container, failed on a test that had never failed.

The same reasoning covers keys as well as comparisons: a scheduled run's dedupe
key is the minute it is due, and two instances with skewed clocks either side of
a boundary compute *different* keys — both unique, so the schedule that should
run once runs twice. The key is taken from `select now()` for that reason.

What is safe, and why, so this is not applied where it costs a round trip for
nothing:

- **Both sides from the app.** Session expiry is computed as
  `new Date(Date.now() + ttl)` and compared against `new Date()`. One clock,
  and skew is invisible to it.
- **Windows wide enough not to care.** A rate limit over ten minutes shifts by
  the skew and nothing else.

The rule is about *boundaries*: a row that was just written, an equality, or a
key two processes must agree on.

## Verify against the symptom, not the diff

A fix for something reported from a running system is not finished until the
symptom has been reproduced and then not reproduced. Two bugs in this repository
looked fixed and were not — a leaked interval that kept firing from a module
graph the reload had replaced, and a database pool closed by the application
that was shutting down. Both were caught by doing the thing again rather than by
reading the change.
